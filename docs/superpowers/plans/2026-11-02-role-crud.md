# Role-based CRUD and Access Repair Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give each role the data management it needs (rooms, guests, admins, own reservations) and restore the database access the app depends on.

**Architecture:** Authorization lives in Postgres (RLS, RPCs, triggers) and in one new Edge Function, `manage-account`, for operations that need the service-role key. Pure decision logic sits in small modules that Vitest can test. Pages stay thin and call `src/lib/db.ts`.

**Tech Stack:** React 19, TypeScript, react-hook-form + zod, Supabase (Postgres, Auth, Storage, Edge Functions on Deno), Vitest.

**Spec:** `docs/superpowers/specs/2026-11-02-role-crud-design.md`

## Global Constraints

- Authorization is enforced by RLS and RPCs in the database. Client-side checks are UX only.
- Never put a service-role key in frontend code or `VITE_` env vars.
- Any command or tool call that modifies the remote Supabase project needs the exact command shown and approved first. Further read-only queries on the live project are also shown and approved first.
- Exploit scenarios that attempt unauthorized writes run only on a test project or Supabase branch, never on STAYSYNC (`atwkcgcajqljaogtgahf`).
- Add new numbered migrations. Do not edit applied ones.
- Half-open ranges `[check_in, check_out)`. Only `confirmed` blocks dates. No same-day bookings. Minimum advance comes from `booking_rules`.
- Use `src/components/ui` components, the existing visual style and the `@/` alias.
- After each task run `npm run typecheck && npm run lint && npm test` and report the results. Before pushing, also run `npm run format:check` and `npm run build`.
- Never stage `supabase/functions/create-staff/index.ts`. It holds the user's uncommitted changes. Stage files by name.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- The Supabase CLI is not on PATH and Docker is not installed. Use `npx supabase` for the CLI, and do not plan on a local stack.

## Review Focus

- A guest has the edit page open while staff confirm or reject the request: the save is refused and the guest is told the request changed. Pinned in Task 2 (`reservationEditErrorMessage`).
- A guest edits dates to start on the day another confirmed stay ends, or to overlap only pending requests: both are allowed. A real overlap with a confirmed stay is refused. Pinned in Task 2 (exploit checks).
- A staff member enters an email with capitals, spaces or no domain: it is normalized or refused before reaching Auth. Pinned in Task 5 (`normalizeEmail`).
- An admin who was deactivated or demoted keeps a stale tab open and calls `manage-account`: it returns 403 based on the current profile. Pinned in Task 5 (`decideAccountAction`).
- A room delete affects zero rows because RLS filtered it: the photos stay and the app reports failure. Pinned in Task 4 (`.select("id")` check and manual step).
